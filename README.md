## 왜 만들었나

국내 은퇴 계산기는 대부분 수익률과 수명을 고정한 단순 계산이고, 세금·건강보험료가 빠져 있어 결과가 낙관적입니다. 해외 도구(Boldin, ProjectionLab)는 확률 시뮬레이션을 쓰지만 미국 제도 기준입니다. 이 프로젝트는 **한국 제도 + 확률 모델 + 계리 모델**을 하나로 묶어 그 빈자리를 채웁니다.

## 이렇게 동작합니다

```
① 단계별 입력 (20세부터): 은퇴 시점 → 자산·소득·저축 → 기본생활비 → 여행 예산 → 연금 → 남길 자산 → 투자 성향 → 최종 확인
② 1만 개 시나리오: 금리·물가·주가(연결된 확률과정) × 부부 각자의 수명·간병(다중상태 모델)
③ 현금흐름: 은퇴 전 저축 → 은퇴 후 기본생활비 우선, 여유가 있을 때만 여행 예산 지출
④ 세금·건보료·보유세·상속세 반영
⑤ 결과: Income Gap, 목표별 달성 확률, 필요 금융자산·필요 저축액, "직접 바꿔보기"(은퇴 시기·저축·생활비·국민연금·투자 성향 슬라이더, 변화 곡선, 주택연금·집 줄이기 비교), "상품 추가해 보기"(주식·예금·연금·보험)
```

## 차별점

1. **목표 기반 구조** — 기본생활(지켜야 할 목표), 여행·취미(조정 가능한 목표), 남길 자산을 나누고, 나쁜 시나리오에서는 선택 지출부터 줄이는 가드레일 규칙을 적용 (보호선 = 생존확률 가중 기대 부족분 현가)
2. **한국 제도** — 국민연금 조기·연기수령, 사적연금 1,500만원 분리과세, 금융소득종합과세, 건강보험료(지역/직장, 피부양자), 재산세·종부세, 상속·증여세
3. **계리 모델** — 통계청 2024 완전생명표 + 코호트 사망률 개선(연령별 연간 0.3~2.5%, 통계청 추이로 검증), 부부 공동생존, 간병 다중상태 마르코프(건강 → 경증 → 중증 → 사망, 장기요양 통계로 보정), 연금 상품(종신·부부형·보증기간·체증·거치형) 수지상등 가격, 생명표 사망률 보존 보정
4. **확률 경제 모델** — ECOS 실데이터로 추정한 실질금리·물가 OU 과정과 피셔 연결, 2요인 채권 가격 해석해, 1년 금리 적분의 정확한 결합분포, 폭락 점프, 파라미터 불확실성, 운용보수
5. **통계적으로 정직한 비교** — 공통 난수 위에서 경로별 차이로 신뢰구간을 계산해 "차이 있음 / 없음"을 판정

> **v39 (2026-10-14):** "실제 상품설명서 2~3개를 넣자"로 시작했는데, **무엇을 받아올지부터 재 보니 방향이 바뀌었습니다.** 스펙 11개를 현실적 범위에서 하나씩 흔들어 보니 **계약체결비용이 영향이 가장 작았습니다**(±0.8%) — 상품설명서에서 찾기 제일 번거로운 숫자인데 제일 안 중요하고, 계약관리비용이 3배 큽니다. 그래서 실명 상품을 모으는 대신 **공시된 사업비 범위의 양 끝**으로 '상품 선택의 폭'을 쟀습니다(`product.choice_spread`). 결과: **사업비가 가장 싼 상품과 가장 비싼 상품의 차이는 6.0%인데, 납입이 끝난 뒤 개시를 65 → 75세로 옮기면 48.5%** 입니다(35세 가구는 5.9% vs 73.7%). **어느 상품을 고르느냐보다 언제부터 받느냐가 8~12배 큰 결정입니다.** 특정 회사 상품이 아니라 공시된 시장 범위라 비교광고 소지도 없습니다. 만들다 한 번 바로잡았습니다 — 처음엔 개시 나이의 폭이 149.7%로 나왔는데, **개시하면 납입도 멈추므로** 납입 중 개시를 섞으면 '덜 내는 효과'가 함께 잡혔던 것입니다. 납입 종료 후만 비교하도록 고쳐 48.5%가 됐고 테스트로 고정했습니다. 교훈: **자료를 모으기 전에 그 자료가 결과를 얼마나 바꾸는지부터 재면, 모을 양이 줄거나 아예 필요 없어진다.** 테스트 74 → 77개.

> **v38 (2026-10-14):** **A/B 비교 그래프**를 넣었습니다 — `바꿔보기`에서 조건을 바꾸면 '지금 계획'과 '바꾼 뒤'의 나이별 남는 돈이 한 그림에 겹쳐 그려집니다(**색 = 계획, 선 모양 = 시나리오**: 실선 보통, 점선 하위 25%). 확률 한 숫자보다 **언제 바닥나는지**가 눈에 들어와, 고객 앞에서 쓰는 화면이 표에서 그림으로 바뀌었습니다. 만들다 보니 리포트의 팬차트에 **범례가 없다는 것**을 발견했습니다 — 코드에 라벨이 있는데 그려지지 않아, 고객이 받는 문서에서 어느 선이 뭔지 알 수 없었습니다. 축·범례 코드를 한 곳(`_lines_svg`)으로 모아 범례를 살리고 같은 코어로 비교 그래프를 만들었습니다.
>
> 이어서 전체를 점검해 덜어냈습니다. **앱과 리포트가 같은 그림을 따로 계산**하고 있어 `fan_rows`·`post_retirement_average`로 합쳤고, 매 시뮬레이션마다 계산하지만 **아무도 쓰지 않던 출력 두 개**(고갈 시점 곡선, 은퇴 후 평균 세금)를 뺐습니다. 안 쓰이는 import 13개와 죽은 함수 `cohort_qx`, 테스트가 이미 덮는 검증 스크립트 3개(`validate*.py`)도 지웠습니다 — 다만 그 중 테스트에 없던 **OU 장기 표준편차** 검증은 버리지 않고 테스트로 옮겼습니다(스크립트와 달리 CI에서 매번 돕니다). 그리고 **앱을 실제로 실행해 보는 연기 테스트**를 처음 넣었습니다. 그동안 앱은 '버전이 맞는가'만 검사해서, 앱이 깨져도 배포한 뒤에야 알았습니다. 테스트 71 → 73개.

> **v37 (2026-10-14):** 또 한 번 **덜어내려고 전면 재측정했는데, 지울 게 없다는 결론**이 나왔습니다. 구성요소 14개를 하나씩 꺼 보니(`scripts/ablate.py`, 대표 가구 2곳) 두 가구 모두에서 몬테카를로 오차 안에 들어온 것은 금리-주식 상관과 폭락 점프 둘뿐이었고, 그마저 꼬리(CTE90)로 다시 재니 점프의 구간이 [−1.3억, +0.25억]로 **"효과가 0"이 아니라 "1만 경로로는 분해가 안 된다"**는 뜻이었습니다. KOSPI의 두꺼운 꼬리는 실증 사실이라 지우면 꼬리위험을 과소평가하게 됩니다. 파라미터 202개 중 **선언만 있고 안 쓰이는 것은 2개**뿐이었습니다. 그래서 방대함의 정체는 군더더기가 아니라 **구조**였습니다 — `run()` 한 함수가 515줄. 경로에 의존하지 않는 계산 6개(보호선 표, 생존·간병 경로, 부모 간병, 주식비중 경로, 연금 현가, 간병보험료)를 순수 함수로 꺼내 **515 → 407줄**로 줄이고, 기준 가구 결과가 **비트 단위로 동일**함을 확인한 뒤 각 함수에 단독 테스트를 붙였습니다(61 → 71개). 덤으로 두 버그를 잡았습니다: 화이트라벨 `tagline`이 설정만 되고 리포트에 안 나오던 것(브랜드 필드 전부가 HTML에 도달하는지 테스트로 고정), 그리고 노트북이 모듈을 옛 코드로 되돌려 버리던 사고의 재발 방지(`scripts/sync_notebook.py` + 불일치 테스트). 고지에 빠져 있던 간병비 물가·더블케어·행동 가정도 채웠습니다.

> **v36 (2026-10-14):** 모델을 세 군데 보완했습니다. **간병비는 일반 물가가 아니라 임금을 따라갑니다** — 사람이 하는 일이라 생산성 향상이 없기 때문입니다(장기요양 수가 2022~2026 평균 4.05% vs 같은 기간 물가 3.02%, 연 1.0%p 차이). 이걸 반영하니 30대 부부의 꼬리 위험(CTE90)이 2.87억 → **6.14억으로 두 배 이상** 뛰었습니다. 그동안 장기 간병 비용을 체계적으로 과소평가하고 있었습니다. **더블케어**(부양하는 부모의 간병을 확률로 계산)와 **행동 가정**(폭락장 패닉 매도, 지출 경직성)도 선택할 수 있게 넣었습니다.

> **v35 (2026-10-14):** 기업이 자기 앱에 붙일 수 있는 **HTTP API**(`retire_sim/api.py`)와 **화이트라벨**(기관 이름·색·로고·고지문)을 넣었습니다. 더 중요한 작업은 그 앞의 정리였습니다 — 입력 변환·선택지 순위·리포트 조립이 전부 Streamlit 앱 안에 있어 화면 없이는 계산을 돌릴 수 없었습니다. `inputs.py`·`advice.py`·`reporting.py` 로 꺼내 앱과 API가 **같은 함수**를 쓰게 했고, 앱이 자체 구현을 다시 만들면 테스트가 잡습니다. 입력 검증도 새로 넣어 잘못된 값이 엔진 안에서 터지는 대신 어디가 틀렸는지 알려 줍니다.

> **v34 (2026-10-14):** 실제 연금보험 상품을 **상품설명서의 숫자 그대로** 넣어 비교할 수 있게 했습니다(`retire_sim/product.py`). 공시이율(시장금리를 평활해 따라가고 **최저보증이율**이 바닥을 받침)·계약체결비용·계약관리비용·해지공제·연금 전환을 모델링합니다. 핵심 결과: 45세·월 50만 원·20년 납입 기준으로 **적립금은 연금보험 1.82억 < 예금 2.10억 < 펀드 2.55억**인데, **살아 있는 동안 돈이 바닥날 확률은 연금보험 0% / 펀드 16% / 예금 34%**입니다. 연금보험이 파는 것은 수익률이 아니라 오래 살 위험을 떠안아 주는 일이고, 적립금만 비교하면 이 상품을 구조적으로 과소평가하게 됩니다. 최저보증이율은 **금리에 대한 풋옵션**이어서 평균으로는 연 4.3만 원이지만 나쁜 쪽 10% 경로에서는 연 16.9만 원입니다.

- OU 최우추정: 가상 데이터에서 장기 평균·변동성 복원 (회귀 속도는 소표본 과대추정 확인 → 실데이터 추정에서 편의 보정)
- 추정된 모수: 물가 장기평균 2.47%±1.02%p, 실질금리 0.73%±0.74%p, 집값 실질상승 1.25%±1.18%p (원자료와 반영 시점은 [docs/SOURCES.md](docs/SOURCES.md))
- 선택지 비교는 경로별 차이로 신뢰구간 계산 (독립 가정 ±1.38%p → ±0.44%p)
- 결정론적 극한에서 **닫힌식과 일치** (`scripts/benchmark_analytic.py`, 12년 최대 오차 0.0)
- 테스트 108개를 커밋마다 자동 실행 (대표 가구 결과 범위, 방향성, 이론값, 생명표·간병·주택연금 수치, 루프 밖 순수 함수 단독 검증, 브랜드 필드 도달, 노트북↔모듈 일치)

### 구성요소 영향도 (`scripts/ablate.py`, 하나씩 꺼 보고 짝지은 신뢰구간으로 판정)

기본생활 유지 확률의 변화. `●`는 몬테카를로 오차를 넘은 것(= 진짜 효과), `○`는 오차 안.

| 끈 것 | 60대 부부 | 30대 부부 |
|---|---|---|
| 제도: 기초연금 | ● −25.1%p | ● −4.9%p |
| 간병: 2단계 마르코프 | ● +15.5%p | ● +16.1%p |
| 세금·건보료 전체 | ● +9.8%p | ● +8.0%p |
| 수명: 코호트 개선 | ● +7.2%p | ● +8.9%p |
| 경제: 운용보수 0.5% | ● +6.0%p | ● +6.2%p |
| 경제: 피셔 연결 | ● −5.9%p | ● −5.9%p |
| 간병: 비용 인플레이션 | ● +5.1%p | ● +6.7%p |
| 제도: 유족연금 | ● −3.9%p | ● −4.1%p |
| 경제: 기간프리미엄 | ● −3.3%p | ● −3.3%p |
| 수명: 사별 효과 | ● −0.9%p | ● −0.5%p |
| 경제: 파라미터 불확실성 | ○ +0.2%p | ● +1.3%p |
| 수명: 장수 불확실성 | ○ +0.1%p | ● +1.0%p |
| 경제: 폭락 점프 | ○ +0.0%p | ○ +0.7%p |
| 경제: 금리-주식 상관 | ○ −0.2%p | ○ +0.0%p |

이 재측정에서 버그 하나가 드러났습니다: 세금을 끄는 스위치가 **연금계좌 인출 자체를 막고** 있어, 30대 부부는 퇴직연금이 동결돼 −19.0%p라는 거꾸로 된 값이 나왔습니다. 세금을 켠 기본 경로는 영향이 없어 앱 결과는 그대로지만(비트 단위 동일 확인), 측정값을 믿고 뭔가를 지웠다면 사고가 났을 자리입니다.
`○`인 둘은 꼬리(CTE90)로 다시 재도 유의하지 않지만, 점프의 구간이 [−1.3억, +0.25억]로 넓어 **분해가 안 되는 것**이지 효과가 0인 것이 아니라서 남겼습니다.

세 전략(ISA·연금계좌·증여)은 기본값이 꺼져 있어 **켜서** 측정합니다 — 금융자산 8억·연금계좌 2억 가구에서 ISA +2.2%p, 연금계좌 +4.7%p, 증여(10년마다 자녀당 5천만 원)는 유지확률 −22.7%p이지만 가족 이전 총액 +2.9억으로 **맞교환이 분명**합니다.

## 사용법

- **웹 앱:** 위 링크에서 한 단계씩 입력 → "이 조건으로 계산하기"

- **로컬:**
  ```bash
  pip install -r requirements.txt

  ```
